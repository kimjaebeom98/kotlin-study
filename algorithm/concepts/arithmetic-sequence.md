# 등차수열 (Arithmetic Sequence)

> PS에서 반복문 없이 O(1)로 합을 구할 때 쓰는 기본 도구.
> 표기 규칙(⭐ ⚠️ 🔍)은 [루트 README](../../README.md#-문서-표기-규칙) 참고.

---

## 1. 등차수열이란

**옆 항과의 차이가 항상 일정한 수의 나열.** 그 일정한 차이를 **공차(common difference, `d`)** 라고 한다.

```
3, 4, 5, 6, 7      → d = 1
2, 5, 8, 11, 14    → d = 3
10, 7, 4, 1        → d = -3   (감소해도 등차수열)
7, 7, 7, 7         → d = 0
```

PS에서 "a부터 b까지의 정수", "n 이하의 3의 배수" 같은 표현이 나오면 전부 등차수열이다.

### 기호

| 기호 | 뜻 |
|:--:|---|
| `a` | 첫째항 |
| `d` | 공차 |
| `n` | 항의 개수 |
| `l` | 마지막항 |
| `S` | 합 |

---

## 2. 세 가지 공식

### 일반항 — n번째 항이 무엇인가

```
aₙ = a + (n - 1) × d
```

첫째항에서 **`n-1`걸음** 갔다는 뜻이다. 1번째 항은 0걸음이므로 `-1`이 붙는다.

```
a = 3, d = 7, n = 10  →  3 + 9 × 7 = 66
```

### 항의 개수 — 몇 개인가

```
n = (l - a) ÷ d + 1
```

"첫째항에서 마지막항까지 몇 걸음(`(l-a)/d`) 갔나 + 출발점 1개".

```
2 ~ 14, d = 3  →  (14 - 2) / 3 + 1 = 4 + 1 = 5개
3 ~ 5,  d = 1  →  (5 - 3) / 1 + 1 = 2 + 1 = 3개
```

⭐ 공차 1인 경우의 익숙한 `max - min + 1`은 `÷ 1`이 생략된 특수 케이스일 뿐이다.

### 합 — ⭐ 핵심

```
S = (첫째항 + 마지막항) × 항의 개수 ÷ 2
  = (a + l) × n ÷ 2
```

**공차가 몇이든 이 공식은 그대로다.** 공차는 오직 `n`과 `l`을 정하는 데만 쓰인다.

마지막항 대신 공차로 표현한 형태도 있다. `l = a + (n-1)d`를 대입한 것뿐이라 같은 식이다.

```
S = n × (2a + (n - 1) × d) ÷ 2
```

첫째항과 공차, 개수만 주어지고 마지막항을 모를 때 편하다.

## 3. 합 공식이 성립하는 이유 — 가우스의 방법

같은 수열을 **뒤집어서 아래에 놓고** 세로로 더한다.

```
   2 +  5 +  8 + 11 + 14
+ 14 + 11 +  8 +  5 +  2
────────────────────────
  16 + 16 + 16 + 16 + 16
```

위쪽은 `d`씩 커지고 아래쪽은 `d`씩 작아져서 **정확히 상쇄된다.** 그래서 세로 짝의 합이 전부 `a + l`로 같다. 이 상쇄가 등차수열의 정의(간격이 일정) 때문에 성립하므로, **공차 값 자체는 아무 상관이 없다.**

- 세로 짝 하나 = `a + l` = **16**
- 짝의 개수 = `n` = **5**
- `16 × 5 = 80` → 수열을 **두 번** 더한 값 → `÷ 2` → **40**

검산: `2 + 5 + 8 + 11 + 14 = 40` ✅

### `÷ 2`가 항상 딱 떨어지는가 — 공차 1이면 그렇다

정수 나눗셈이라 나머지가 버려지는데, **공차 1**에서는 `(a + l)`과 `n` 중 최소 하나가 반드시 짝수라 안전하다.

- `n`이 홀수면 → 양 끝의 홀짝이 같다 → `a + l`이 짝수
- `n`이 짝수면 → 그 자체가 짝수

⚠️ **공차가 1이 아니면 이 보장이 깨질 수 있다.** `(a + l) × n`은 여전히 짝수지만, 곱한 뒤에 나누지 않고 `n / 2` 같은 식으로 **먼저 나누면** 값이 손상된다. 반드시 **곱한 다음 나눌 것.**

```kotlin
(a + l) * n / 2     // ✅ 곱셈 먼저
(a + l) * (n / 2)   // ❌ n이 홀수면 버려진다
```

## 4. Kotlin 구현

### 표준 라이브러리 — `step`

코틀린은 `step`으로 공차를 지정한 범위(`IntProgression`)를 만든다.

```kotlin
// 🔍 실제 실행 결과
(2..14 step 3).toList()      // [2, 5, 8, 11, 14]
(2..14 step 3).sum()         // 40
(2..14 step 3).count()       // 5
(3..100 step 3).last         // 99    ← 끝을 100으로 줘도 99에서 멈춘다
(3..100 step 3).sum()        // 1683
(10 downTo 1 step 3).toList()// [10, 7, 4, 1]
(5..3).toList()              // []    ← 역방향은 예외가 아니라 빈 범위
```

⭐ `.last`는 **실제로 수열에 존재하는 마지막 값**을 계산해 준다. 마지막항을 직접 구하기 번거로울 때 유용하다.

⚠️ `step`에는 **양수만** 들어간다. 감소 수열은 `downTo`를 쓴다.

⚠️ `sum()`, `count()`는 전부 **O(n) 순회**다. 항이 많으면 공식을 써야 한다.

### O(1) 합 — 범용 함수

```kotlin
fun sumOfProgression(first: Long, last: Long, step: Long): Long {
    require(step != 0L) { "step must not be zero" }
    val n = (last - first) / step + 1        // 항의 개수
    if (n <= 0) return 0                     // 방향이 안 맞으면 빈 수열
    val realLast = first + (n - 1) * step    // ⭐ 실제 마지막항으로 보정
    return (first + realLast) * n / 2
}
```

```kotlin
// 🔍 실제 실행 결과
sumOfProgression(2, 14, 3)          // 40
sumOfProgression(3, 100, 3)         // 1683
sumOfProgression(1, 100, 1)         // 5050
sumOfProgression(10, 1, -3)         // 22      (10 + 7 + 4 + 1)
sumOfProgression(5, 3, 1)           // 0       (빈 수열)
sumOfProgression(0, 10_000_000, 1)  // 50000005000000
```

## 5. ⚠️ PS 함정 4가지

### ① 마지막항 ≠ 범위의 끝

**수열에 실제로 존재하는 값**이어야 한다. "1~100 중 3의 배수"의 마지막항은 100이 아니라 **99**다.

```
❌ (3 + 100) × 33 / 2 = 1699   ← 100은 수열에 없다
✅ (3 +  99) × 33 / 2 = 1683
```

`n`은 정수 나눗셈 덕에 우연히 맞는 경우가 많아서, **합을 구할 때 틀린 마지막항을 그대로 넣는 실수**가 자주 나온다. `l = a + (n-1)d`로 한 번 보정하고 쓰는 습관이 안전하다.

### ② 오버플로우는 **연산 시점**에 터진다

`Int`끼리의 곱셈은 결과가 `Int`로 계산된 뒤 넘친 상위 비트를 **조용히 버린다**(에러 없음). 반환 타입만 `Long`으로 바꿔도 소용없다.

```kotlin
// 🔍 a = 0, l = 10_000_000, n = 10_000_001
(a + l) * n / 2                 // → 143223616        ❌
(a.toLong() + l) * n / 2        // → 50000005000000   ✅
```

⭐ **곱셈 이전에** 한쪽을 `Long`으로 올릴 것. 반환할 때 `.toLong()`은 이미 늦었다.

⚠️ 랩어라운드 결과가 꼭 음수인 것도 아니다. 위처럼 양수로 나오면 훨씬 알아채기 어렵다.

### ③ `sum()`은 원소 타입 그대로 누적한다

```kotlin
// 🔍 0..10_000_000
(a..l).sum()                 // → -2004260032      ❌ Int로 누적
(a..l).sumOf { it.toLong() } // → 50000005000000   ✅ 원소를 먼저 승격
```

### ④ 역방향은 예외가 아니라 빈 수열

`a > b`일 때 `a..b`는 에러를 내지 않고 **비어 있다.** 합이 조용히 `0`이 된다.

```kotlin
(5..3).sumOf { it.toLong() }   // → 0
```

⭐ 대소관계가 보장되지 않으면 `minOf` / `maxOf`로 **정규화 먼저**.

## 6. 자주 쓰는 형태

| 구하는 것 | 식 | 예 |
|---|---|---|
| `1 ~ n`의 합 | `n(n+1)/2` | `1~100` → 5050 |
| `a ~ b`의 합 | `(a+b)(b-a+1)/2` | `3~5` → 12 |
| `n` 이하 `k`의 배수의 합 | `k × m(m+1)/2`, `m = n/k` | `100` 이하 `3`의 배수 → `3 × 33×34/2` = 1683 |
| 홀수 `n`개의 합 | `n²` | `1+3+5+7` = 16 |
| 짝수 `n`개의 합 | `n(n+1)` | `2+4+6+8` = 20 |

⭐ **`n` 이하 `k`의 배수의 합**은 특히 자주 나온다. `k`를 통째로 묶어내면 `1~m` 합 문제로 환원된다는 게 핵심이다.

## 7. 정리

| | |
|---|---|
| ⭐ | 합 = `(첫째항 + 마지막항) × 개수 ÷ 2` — **공차와 무관하게 동일** |
| ⭐ | 공차는 `n = (l-a)/d + 1`과 마지막항을 정하는 데만 쓰인다 |
| ⭐ | 반복문 O(n) → 공식 O(1). 범위가 `10^9` 넘으면 공식 외엔 답이 없다 |
| ⚠️ | 마지막항은 범위의 끝이 아니라 **수열에 존재하는 값** |
| ⚠️ | 오버플로우는 곱셈 시점에 터진다 — 미리 `Long`으로 |
| ⚠️ | 나누기는 **곱한 다음에** — `(a+l)*n/2`, `(a+l)*(n/2)` 아님 |
| ⚠️ | 역방향 범위는 예외가 아니라 빈 수열 → 조용한 `0` |
