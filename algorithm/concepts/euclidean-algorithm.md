# 유클리드 호제법 (Euclidean Algorithm)

두 정수의 **최대공약수(GCD)** 를 나눗셈 몇 번으로 구하는 방법. "호제(互除)"는 "서로 나눈다"는 뜻이다.

## 1. 핵심 아이디어

```
gcd(a, b) = gcd(b, a % b)
gcd(a, 0) = a
```

**"큰 수를 작은 수로 나눈 나머지"로 문제를 계속 작게 줄여가다가, 나머지가 0이 되는 순간의 나누는 수가 답**이다.

```
🔍 실제 실행 결과 — gcd(1071, 462)
gcd(1071, 462) = gcd(462, 147)   [ 1071 = 462 × 2 + 147 ]
gcd(462, 147)  = gcd(147, 21)    [  462 = 147 × 3 +  21 ]
gcd(147, 21)   = gcd(21, 0)      [  147 =  21 × 7 +   0 ]
나머지가 0 → 답은 21
```

세 번의 나눗셈만으로 21을 찾는다. 소인수분해해서 비교하는 것보다 훨씬 빠르다.

---

## 2. 증명 — 왜 이게 최대공약수를 구하나

`a = b × q + r` (`q`는 몫, `r = a % b`)일 때, `gcd(a, b) = gcd(b, r)`이 성립함을 보인다.

### 준비 — 나눗셈의 기본 성질

**성질 1**: `d`가 `x`와 `y`를 둘 다 나누면, `d`는 `x + y`도 나눈다.
`x = d×m`, `y = d×n`이면 `x + y = d×(m+n)`. `m+n`도 정수이므로 `d`의 배수.

**성질 2**: `d`가 `x`와 `y`를 둘 다 나누면, `d`는 `x - y`도 나눈다.
같은 방식으로 `x - y = d×(m-n)`.

> 참고로 수학에서는 "`d`가 `x`를 나눈다"를 `d | x`라고 짧게 쓴다. 여기선 코틀린의 비트 OR 연산자(`|`)와 헷갈리지 않도록 매번 말로 풀어 쓴다.

### 본 증명 — 공약수 집합이 완전히 같다

`D` = `a`와 `b`의 공약수 전체, `D'` = `b`와 `r`의 공약수 전체.

**① `D`의 원소는 전부 `D'`에도 속한다**

`d`가 `a`, `b`를 나눈다고 하자.
- `d`가 `b`를 나누므로, `d`는 `b×q`도 나눈다 (배수도 나눔)
- `d`가 `a`도 `b×q`도 나누므로, 성질 2에 의해 `d`는 `(a - b×q)`도 나눈다
- `a - b×q = r` (나눗셈의 정의)
- 따라서 `d`는 `r`을 나눈다. `d`가 `b`를 나누는 것도 이미 확인했으니 `d ∈ D'`.

**② `D'`의 원소는 전부 `D`에도 속한다**

`d`가 `b`, `r`을 나눈다고 하자.
- `d`가 `b`를 나누므로, `d`는 `b×q`도 나눈다
- `d`가 `b×q`도 `r`도 나누므로, 성질 1에 의해 `d`는 `(b×q + r)`도 나눈다
- `b×q + r = a`
- 따라서 `d`는 `a`를 나눈다. `d`가 `b`를 나누는 것도 이미 확인했으니 `d ∈ D`.

### 결론

①과 ②로 `D`와 `D'`가 서로를 완전히 포함하므로 **두 집합은 동일하다**. 같은 집합이면 그 안의 최댓값도 같다.

```
gcd(a, b) = D의 최댓값 = D'의 최댓값 = gcd(b, r)   ∎
```

특정 숫자가 아니라 `a`, `b`, `d`, `q` 같은 임의의 값으로 증명했으므로 모든 정수 쌍에 대해 성립한다.

## 3. Kotlin 구현

```kotlin
tailrec fun gcd(a: Long, b: Long): Long = if (b == 0L) a else gcd(b, a % b)
fun lcm(a: Long, b: Long): Long = a / gcd(a, b) * b
```

```
🔍 실제 실행 결과
gcd(48, 18) = 6
lcm(4, 6)   = 12
gcd(5, 0)   = 5      gcd(0, 5) = 5
gcd(17, 5)  = 1       (서로소)  lcm(17, 5) = 85
```

⭐ **`tailrec`을 붙인다.** 재귀 호출이 함수의 마지막 동작이라 컴파일러가 반복문으로 바꿔준다. `gcd`는 재귀 깊이가 매우 얕아서(아래 참고) `tailrec` 없이도 실용적으로 문제없지만, 습관으로 붙여두면 안전하다.

`kotlin.math`에는 `gcd`/`lcm`이 없다. PS에서 자주 나오는데도 표준 라이브러리에 없어서, 위 두 줄을 그대로 외워두는 게 낫다.

### 왜 이렇게 빠른가

```
🔍 gcd(922337203685477580, 123456789123456) = 12
   걸린 시간 = 38 마이크로초
🔍 (Long.MAX_VALUE, 1) 같은 극단적 케이스도 → 1단계면 끝
```

나눗셈 한 번마다 두 수 중 하나가 최소 절반 이하로 줄어드는 성질 덕분에 `O(log(min(a,b)))`로 끝난다. `1`부터 작은 수까지 다 나눠보는 완전탐색(`O(min(a,b))`)과 비교가 안 될 만큼 빠르다.

## 4. ⚠️ PS 함정

### ① `lcm`은 곱셈보다 나눗셈을 먼저

```kotlin
a / gcd(a, b) * b     // ✅ 나눗셈 먼저
a * b / gcd(a, b)     // ❌ a*b 가 먼저 오버플로우될 수 있다
```

```
🔍 a = 6,000,000,000, b = 4,000,000,000
a * b                    = 5553255926290448384   ← 이미 Long 범위(약 9.2×10¹⁸)를 넘어 랩어라운드됨
a * b / gcd(a,b) (틀림)   = 2776627963
a / gcd(a,b) * b (맞음)   = 12000000000
```

`a`, `b`가 각각 `Long` 범위 안이어도 **곱이 먼저 넘칠 수 있다.** `gcd`로 먼저 나눠서 크기를 줄인 다음 곱해야 안전하다.

### ② 음수를 넣으면 부호가 이상해진다

```
🔍 gcd(-12, 18) = 6     (우연히 맞음)
🔍 gcd(12, -18) = -6    ❌ 음수가 나옴
```

`%` 연산이 왼쪽 피연산자의 부호를 따라가기 때문이다. 최대공약수는 정의상 항상 양수이므로, 음수가 들어올 수 있으면 먼저 절댓값을 취한다.

```kotlin
gcd(abs(a), abs(b))
```

### ③ 세 개 이상의 최대공약수/최소공배수는 `reduce`로 묶어나간다

```kotlin
val nums = listOf(24L, 36L, 60L)
nums.reduce { x, y -> gcd(x, y) }   // 12
nums.reduce { x, y -> lcm(x, y) }   // 360
```

`gcd(gcd(24,36),60)`처럼 둘씩 순서대로 묶어도 결과가 같다. 최대공약수·최소공배수 둘 다 이 성질(결합법칙)을 만족한다.

---

## 5. 정리

| | |
|---|---|
| ⭐ | `gcd(a,b) = gcd(b, a%b)`, `gcd(a,0) = a` — 나머지가 0이 될 때까지 반복 |
| ⭐ | 증명의 핵심: `d`가 두 수를 나누면 그 합·차도 나눈다 → 공약수 집합이 절대 안 바뀐다 |
| ⭐ | `O(log(min(a,b)))` — 완전탐색과 비교가 안 될 만큼 빠름 |
| ⚠️ | `lcm`은 `a/gcd(a,b)*b` — 곱셈 먼저 하면 오버플로우 |
| ⚠️ | 음수 입력은 `gcd`가 음수를 반환할 수 있음 — 먼저 `abs()` |
| ⚠️ | `kotlin.math`에 `gcd`/`lcm`이 없다 — 직접 구현해서 외워둘 것 |
